## 学習の流れ

1. **単純なLLM呼び出し**：評価手続と証跡を入力して評価する。
2. **基本RAG**：入力に含まれない社内規程や証跡を検索する。
3. **文脈を保つ応用RAG**：条件・例外・版・適用時点を含めて根拠を取得する。
4. **単一ReAct**：観測結果に応じて次の検索・照合・保留を選択する。
5. **サブエージェント**：調査ごとに文脈を分け、根拠付きの部分結果を統合する。
6. **総合比較**：品質、根拠の追跡可能性、費用、レビュー負担から必要十分な構成を選ぶ。

各段階では「実行 → 成功例 → 限界が現れるケース → 原因分析 → 改善 → 再評価」を繰り返します。共通の題材は架空の購買承認の監査評価です。
