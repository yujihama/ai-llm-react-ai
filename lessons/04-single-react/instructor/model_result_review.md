# モデル選択例の判定と根拠の照合

保存済みの行動・観測・最終出力を、規程と証跡の原文に照らして別途確認した記録です。各条件1回の実行であり、一般的な精度や再現性を示すものではありません。行動の選択方法は各例のprovenance.jsonを参照してください。

| 条件 | 結果 | 根拠の確認 |
| --- | --- | --- |
| C_deferred | 5手で終了、C1〜C4充足 | 規程全文と予算明細を取得し、委任例外の全条件を説明している |
| C_unavailable | 6手で終了、C2のみ保留 | 予算明細の読取失敗と検索0件を受け、未確認事項と追加確認を示している |

C_deferredでは、規程の適用期間と部門、正式委任、発行時の委任者と承認時の受任者の在任、期間・取消・上限、予算の事前承認、部門・ID・明細・品目・金額、承認記録からの追跡を引用と説明で確認できます。

C_unavailableでは、予算IDへの参照と本文の取得を区別しています。未提示の予算承認日を補完せず、資料が存在しない、予算が未承認である、条件不充足である、という断定もしていません。C1・C3・C4の確認済み部分を維持し、C2に必要な予算明細の情報だけを保留しています。

両例のcompareはC3の時刻比較1回です。E-A04 L08の承認確定09:00とE-O04 L06の発注確定10:00をJSTの日時として渡し、厳密な「前」をltで照合しています。予算承認時期、金額上限、ID等まで比較ツールで検証したわけではありません。それらは取得原文と最終説明の対応を点検します。

C1は対象取引と承認確定、基準時点までの取消等なし、C4は取引ID・版・税抜額の一致によって支持されます。両例の引用は行動時点で観測済みであり、原文と説明の照合で修正を必要とする不整合は見つかりませんでした。これは実行系の形式検査に加えた内容の照合であり、監査意見や統制全体の有効性の判断ではありません。

実行系はこれらの正答をモデルへ教えていません。また、このファイル照合だけではモデルの内部処理や転送前の修正有無までは検証できません。実行の出典・中継記録と併せて扱ってください。
